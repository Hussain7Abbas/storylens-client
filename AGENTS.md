# Desktop client instructions

This repository is the desktop client for Story Lens and has independent Bun dependencies. When checked out as a submodule of the umbrella project, also follow its root `AGENTS.md`. Runtime code must use Node/Electron APIs, not Bun APIs. See the [desktop guide](https://github.com/Hussain7Abbas/storylens/blob/develop/docs/client.md).

- `src/providers/` owns Claude Code, Codex and Gemini CLI discovery/execution. Gemini uses `--acp` initialize/session-new model discovery and stdin headless JSON execution, with only `default` effort. Its `geminiPath` setting defaults to `gemini` for legacy files and is exposed through the narrow settings IPC. `gemini.ts` writes per-job system settings to disable hooks, MCP, extensions, skills, local tool commands and instruction discovery; only explicit web research allows Gemini web tools. Escape literal `@` in stdin to prevent CLI file expansion. Keep image generation Codex-only and protocol version 2 unchanged. Pass prompts by stdin and never through a shell. Validate requested model/effort against the catalog. Preserve the located CLI's runtime directory on PATH for both catalog discovery and execution.
- `src/service.ts` owns command admission and limits; `src/server.ts` owns the loopback HTTP interface. It accepts browser-extension origins and the Story Lens dashboard origins in `DASHBOARD_ORIGINS` (production and `localhost:3040`), always behind the pairing token; an `OPTIONS` route answers CORS and private-network preflights. The crawler's API client reads and writes names in the crawl's response language (`nameAr`/`nameEn`, aliases included), sends a client `id` on every create (keywords also `versionId`), treats 409 `KEYWORD_NAME_TAKEN`/`ALIAS_NAME_TAKEN` as already saved, and uses stored text as typed (the API no longer HTML-escapes it). Do not import Electron into these modules. Protocol 2 requires `responseLanguage` (`en` or `ar`) on every `ExecutePrompt` request; its optional `webSearch` flag is the only way to give a provider web tools (Claude `WebSearch`/`WebFetch`, Codex `web_search="live"`, Gemini `google_web_search`/`web_fetch`). `POST /GenerateImage` accepts optional `promptIsDescription` (advertised as `features.imagePromptInput` in protocol 2): true passes the saved/edited description directly to the image model, without a text call; omission preserves the original flow. Otherwise it first writes a self-contained English visual description using the selected Codex model through `executeProvider`, then draws from that description and returns it as `revisedPrompt` (or the image tool’s revised description). Both steps share one admission slot, cancellation signal and a 300-second total deadline; reject empty or over-4000-character descriptions before drawing. Never return the raw chapter/instruction source as the image prompt. Image generation runs only on Codex (`src/providers/image.ts`, `image_generation` feature) and shares the concurrency limit; read generated files only from `$CODEX_HOME/generated_images/` or the job's disposable directory.
- `POST /AccountSession` (`{ account: { apiUrl, token } | null }`) is how the paired extension shares its Story Lens session; it is stored as `account` in the private settings file (HTTPS API URLs, or HTTP only on localhost) and `null` clears it. `client:state` must never return the account token to the renderer.
- `src/backend/api.ts` is the main-process Story Lens API client used by crawling; the shared `apiUrl` is the API origin and every call goes to the reader API under `USER_API_PREFIX` (`/api/user`) (novels, categories, natures, keywords, aliases, versions; nested query params in `key[field]` form). Every call sends `X-Client-Version: desktop/<version>` from `src/version.ts` (read from the shipped `package.json`), and a 426 becomes a `CLIENT_OUTDATED` error; keep all API calls in this client so they carry it. See [API and data compatibility](https://github.com/Hussain7Abbas/storylens/blob/develop/docs/compatibility.md). `src/crawl/` owns the wiki crawler: `page.ts` downloads and parses one public HTML page (no local/private hosts, redirects re-checked, 5 MB cap, same-site crawlable links only), `prompt.ts` builds and parses the per-page prompt (descriptions in the model's own words, aliases, versions, parent suggestions, picked links), `merge.ts` merges phases into the character table, and `session.ts` runs one crawl at a time as sequential phases through `PromptService.executePrompt` (waits while `BUSY`). Keep these modules free of Electron imports and cover them in `test/crawl.test.ts`.
- `src/desktop/` owns main, preload, and renderer. Keep Node integration off, context isolation and sandbox on, and preload IPC narrow. The window has **Settings** and **Crawling** tabs; crawl IPC (`crawl:*`) passes only validated inputs and row keys, and the renderer re-renders only changed table rows that are not being edited.
- Keep credentials in private app settings. Never log pairing token, page HTML, prompts, or output.
- Run `bun run typecheck`, `bun test`, and `bun run build` (or the matching Makefile targets). When working in the umbrella checkout, root rules also require extension/backend typechecks. Keep this file and docs current.
- `.github/workflows/build.yml` tests and packages Windows x64 NSIS, macOS x64/arm64 DMGs, and Linux x64 AppImage/deb on native runners. Published GitHub releases (including prereleases) build their tag and must match `v<package.json version>`; only after every package job passes does the restricted publish job attach all installers and `SHA256SUMS`. Branch/PR/manual runs only upload workflow artifacts. Keep release filenames unique by OS and architecture; rerunning a release replaces its matching assets. Local packaging commands are `dist:win`, `dist:mac`, and `dist:linux` (and matching Makefile targets). Packages are unsigned; native installation, pairing and tray smoke checks remain release checks.

The settings window links to website/privacy/terms. Only those exact HTTPS URLs may open through Electron shell.openExternal; retain the external URL allowlist and denied window creation.

- Desktop visual identity follows Ink & Iris (`apps/website/design-system/MASTER.md` in the umbrella): light/dark tokens in `src/desktop/style.css`, self-hosted Inter and Lucide at 1.75 stroke. The build copies the font and approved Lensbook icon into `dist/desktop`. Packaging uses `build/icon.png` (1024px), `build/icon.icns` for macOS, and `build/icon.ico` for Windows. Shared source and regeneration instructions live in umbrella `docs/branding/`. System/Light/Dark appearance persists in renderer local storage. Button actions have tooltips, busy states and error feedback; status updates must preserve unsaved form edits.
- `keepInSystemTray` is a validated boolean in private settings, default true for new and legacy files. The narrow save IPC accepts it; tray-only changes must not restart the loopback service. Main owns the Tray, restricted Open/Quit menu, hide-on-close, restore on activation/second instance, and explicit quit guard. Disabled tray or tray creation failure uses quit-on-close. Do not introduce Electron imports into configuration/service/server. Test settings migration/persistence and window/tray lifecycle; Windows tray behavior still needs native Windows verification.

`/GenerateImage` additionally accepts optional `referenceImageUrls` (at most eight). Advertise optional `features.imageReferences: true` within protocol 2. `providers/image.ts` loads bounded public HTTP(S) PNG/JPEG/WebP references (8 MB each, 24 MB total, redirects rechecked), attaches them through Codex `--image` and maps each attachment to its original URL in the prompt. Keep inputs in a separate temporary folder outside the generated-output search path, so an input can never be mistaken for a generated image. Downloads and CLI work share cancellation. Old clients/requests without references remain supported. Cover scene selection stays in the extension's editable prompt; all desktop image jobs remain Codex-only.
